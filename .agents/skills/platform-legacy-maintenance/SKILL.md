# 平台遗留代码维护

依据证据进行行为保持型修改，并在结构调整前先补充特征测试以固化当前行为。

## 工作流程

1. 识别调用方、配置分支、功能开关、持久化边界，以及最小且稳定的行为表面。
2. 使用聚焦的特征测试记录当前行为，覆盖租户上下文、空值与错误路径，以及启用和禁用状态下的实现。
3. 将机械性重构与行为变更分开。确保每份差异都便于审查，并避免顺手清理调用链之外的代码。
4. 除非用户明确批准契约变更，否则保留公共数据传输对象、配置名称与默认值、数据库兼容性以及回滚路径。
5. 连同上游模块运行受影响模块的测试，比较修改前后的行为，并记录所有有意作出的兼容性决策。

对于 JDBC 存储，不得重新引入运行时数据定义语句；应通过 `database-migrations` 按先扩展、后收缩的方式迁移。选择模型提供方时，保留共享网关和条件化组件约定。当仓库证据与用户要求的兼容性目标冲突时，停止修改并说明冲突。

不得改写用户无关变更，不得提交、推送或部署；没有测试证据时，不得声称已经兼容。
