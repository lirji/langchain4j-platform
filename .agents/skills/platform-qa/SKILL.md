# 平台质量验证

依据可观察的验收标准和变更风险，给出如实的质量结论。

## 工作流程

1. 明确验证目标、版本、环境、依赖、测试数据和已知限制。
2. 将每项验收标准按需映射到正常、边界、无效输入、权限、租户、重试与恢复以及兼容性用例。
3. 优先执行确定性的单元或模块测试，其次使用安全的本地主机集成链路。不得推测或触碰生产环境。
4. 为每个用例记录环境准备、准确命令或步骤、预期结果、实际证据，以及通过、失败或受阻状态。
5. 区分产品缺陷与环境故障。修复后重新运行失败用例和聚焦的回归测试集。

相关链路发生变化时，检查 `TenantContext` 清理、内部令牌转发、功能开关、异步状态转换、检索增强生成排序、工作流终态以及错误契约。不得将未执行或因外部条件受阻的用例标记为通过。
