# 平台 Java 功能开发

交付能够满足目标行为的最小纵向功能切片。

## 仓库约束

- 设计前阅读根目录 `AGENTS.md`、相关模块代码、测试、配置和主题文档。
- 跨服务数据记录统一放入 `platform-protocol`，不要在各服务中重复定义传输契约。
- 跨服务调用必须保留内部 JWT 中的租户与部门上下文；测试结束时清理 `TenantContext`。
- 大语言模型调用必须置于可模拟的接口之后，并通过共享的 LiteLLM 兼容网关路由模型提供方。
- 遵循既有的“接口加条件实现”模式。数据库变更必须使用带版本的迁移，并按先扩展、后收缩的顺序实施。

## 工作流程

1. 追踪当前请求链路，说明可观察目标、受影响模块、风险以及非目标范围。
2. 定义验收用例，覆盖无效输入、权限校验、租户隔离、失败路径和兼容性。
3. 实现精简的端到端功能切片；在可行时使用不可变的请求与响应模型。
4. 在变更模块中补充聚焦的 JUnit 5 测试。除非需要验证 Spring 装配本身，否则优先使用结合 Mockito 与 AssertJ 的普通 Java 对象测试。
5. 使用 `-am` 运行范围最小的模块测试，检查实际差异，然后同步更新受影响的文档。

未经明确授权，不得提交、推送、部署、修改密钥或扩大需求范围。报告准确的命令及其结果；不得将未执行的检查描述为已通过。
