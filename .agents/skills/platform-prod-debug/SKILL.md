# 平台类生产问题诊断

建立从症状到原因的完整证据链。仅要求诊断并不代表已经授权修改代码。

## 调查约束

- 明确环境、时间窗口、受影响租户、链路标识、入口端点、预期行为以及近期变更。
- 分别追踪边缘认证、内部 JWT 转发、服务调用、事件与事务发件箱状态、持久化和 LiteLLM，不要将它们视为同一个故障域。
- 将密钥和用户内容视为敏感信息：在记录与输出中遮蔽令牌、凭据、个人身份信息、提示词和文档正文。
- 明确区分已确认事实、假设、实验以及已排除原因。

## 工作流程

1. 使用最小且安全的输入，在本地或用户授权的测试环境中复现问题。
2. 沿完整调用链关联链路标识和配置开关。
3. 优先验证信息增益最高的假设；不得修改生产环境，也不得猜测凭据。
4. 使用 `file:line` 或运行时证据说明根因、影响范围和恢复方案。
5. 如果修复已获授权，先添加回归测试，再实施范围最小的修复，重新运行受影响链路，并说明仍需执行的运维检查。

未经明确授权，不得部署、重启服务、修改数据或调用生产端点。
