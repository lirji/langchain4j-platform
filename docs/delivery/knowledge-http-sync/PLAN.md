# HTTP知识源同步第一期

- 授权：用户选择HTTP API产品说明/FAQ同步，继续实施；持续授权任务分支、本地提交、正常合并推送main。不包含部署。
- S1：配置受控HTTP增量连接器、持久化检查点和来源记录映射、定时调度、状态/手动轮询API。
- S2：聚焦行为、HTTP边界、真实MySQL事务/CAS/迁移验证，文档同步与Git交付。
- 现状：使用knowledge-service的IngestionSubmissionService、ingest-api角色与既有worker；无新服务/中间件/依赖。
- 范围：新增/更新、显式删除退出检索及撤权、内容去重、来源单调版本、防同版本异内容、待处理页恢复、租户/执行身份隔离。用户补充图片要求覆盖删除传播，采用Registry原子墓碑阻止旧worker复活；删除后重建使用新文档ID。不从全量列表缺项推断删除，不物理擦除历史存储。
- 源契约：GET固定配置URL?limit=25&cursor=<opaque>；JSON items[{id,revision,title,content,deleted:false}],nextCursor。revision是每条记录正整数单调版本；同页ID唯一；来源应提供可重放增量页，最终空页可以返回原游标。
- 持久化：V7扩展迁移新增两表；SQL位于MyBatis XML；来源配置指纹禁止静默改端点/身份，凭据轮换允许。短事务同时提交记录成功版本和页内位置，网络调用在事务外；CAS租约拦截旧执行器。
- 安全边界：来源仅部署配置可写，HTTPS默认、无重定向、无动态下一页URL；token不存储/输出、不转发内部JWT。服务身份必须由管理员授权，文档更新沿用现有ReBAC。查询/手动触发只允许绑定租户与用户且具备ingest权限。
- 验收：重复页不重复生成embedding；A→B→A建立新文档版本；不同来源/租户隔离；任务未READY不推进游标；提交响应丢失与重启重放同一任务；坏数据/HTTP错误不推进；删除失败不推进、成功后不可检索且迟到提交不能复活；并发租约只有一个领取者；旧租约不能写检查点；映射与页内位置事务原子；旧接口/默认关闭保持兼容。
- 外部真实API地址、鉴权及样例未提供：实现上述明确契约并以本地HTTP服务器验证，不宣称实际业务源已接通。
