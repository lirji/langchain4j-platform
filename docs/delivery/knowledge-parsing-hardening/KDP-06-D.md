# KDP-06-D：切分与增强成本治理

按已批准顺序接续 OCR 验收；本阶段已实现并通过本地完整回归，最终小范围兼容补测见 TEST_RESULT。保留缺省 recursive 与关闭 Contextual，不凭合成样本改变线上策略。

## 实施边界与考虑

1. 语义窗口现在整文一次 embedAll，且宽泛降级会吞掉租约/预算失败。复用条数/token/字节批次，按文档共享模型调用次数和估算输入 token 预算；失租/预算必须停止，普通模型故障可降级但标记实际策略。
2. Contextual 每块重复文首窗口会把后半部章节交给不相关上下文。优先使用当前位置及邻近块、章节标题；完整 prompt 纳入预算，显式限制前缀输出，原文与生成前缀继续分离。
3. 计数采用现有 tokenizer 的保守本地估算，不冒充提供方账单；请求失败也占调用预算，不因降级“退还”。每次准备尝试有独立上限，任务重试次数另有上限；已绑定快照重试仍零模型调用。
4. GraphRAG 现有装配是 RuleBasedGraphExtractor，当前无 Graph LLM 计费调用；不为假设中的模型新增框架。
5. parent_text 复用有检索兼容成本，先计量 metadata/父块重复字节并设整文容量上限，不贸然拆成另一张父块存储或删除既有引用字段。
6. 以冻结结构语料和确定性多主题向量夹具比较内容/定位/主题边界、调用/token/载荷；nearest-rank 短文盲区用明确用例记录，可选线性分位策略通过受控实验后开放，缺省不变。真实 Recall、引用判定和金额需要真实评测集/提供方用量，报告未测，不伪造收益。

## 验收

跨语义窗口/上下文/最终 embedding 总预算可阻止下一调用；批次和模型返回校验有效；失租不降级继续计费；长文尾部获得邻近正文；增强开关与旧 SPI 兼容；父块引用保留而总载荷有界；实际降级可见；完整知识库及相关上游回归，记录生效路径与未覆盖项。


## 最终行为与取舍

- `IngestionModelWork` 随一次准备显式传递，覆盖内置语义窗口、Contextual 和最终 embedding；先拒绝窗口数量/单窗/累计预算，再允许分批调用。失败逻辑调用仍记账；失租/资源异常不能吞成递归降级。普通模型故障保留可见的 `recursive-fallback`。
- 每份准备缺省最多 512 次逻辑模型调用、1000000 估算输入 token；Contextual 最多 128 次、单提示 8192 估算 token、前缀 256 token（请求参数和返回后双重约束）。不是网关租户账单替代品；现有平台预算、审计与模型装饰器继续生效。
- 语义最近秩算法保持缺省；`RAG_CHUNKING_SEMANTIC_INTERPOLATE_PERCENTILE=true` 开启线性分位候选，3 句多主题夹具从 1 块变 2 块，同主题不误切。尚无真实 Recall 增益证据，不默认开启。
- 上下文窗口使用当前章节、父块或同章相邻块，避免文首偏置；`breadcrumb` 和旧 `section` 都隔离章节。生成前缀超长则整段弃用，完整原文保留；`contextual_status` 区分应用/回退/前缀超限。
- 所有 metadata UTF-8 JSON 编码缺省最多 16 MiB，在最终 embedding 前校验；不拆父块存储，不删除 parent_text 契约。处理版本 v4，策略、关键预算和生成配置进入快照，已绑定历史结果继续直接恢复。
- 新指标 `rag.ingest.model.logical.calls` / `estimated.input.tokens`（stage）、`rag.ingest.metadata.bytes` / `repeated.parent.bytes`、`rag.chunk.actual` 和 `rag.contextual.result` 只有固定标签；失败准备也计逻辑请求。网关/SDK 重试可能放大真实 HTTP 次数；split worker 已将 embedding 与 gateway SDK retries 置 0，由 durable job 持有重试权。combined/自定义 SDK 需按真实配置折算。
