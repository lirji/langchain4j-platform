# KDP-06-C：选择性 PDF OCR

接续 `1faa657`。用户已明确按普通企业常见场景推进，不等待业务样本；本阶段代码和本地专项验收通过。

## 范围与考虑

- 以中英印刷体扫描 PDF、数字原生/扫描混合页、页面旋转和图片占主要区域的技术资料为主。手写、复杂跨页表格和任意多栏版面不承诺正确率；合成样本不代表真实检索收益。
- 优先保留原生文本，按页检测缺少文本或大图区域后选择 OCR；记录来源页、执行策略与置信告警，不能把少量页眉当完整正文，也不能简单重复拼入原生层和 OCR 层。
- 使用本地 Tesseract 5 CLI 与英/简体中文语言包，不把文档上传外部服务。只在专用解析子进程中执行，固定参数、最小环境、单线程；页数/像素/输出/单页时间/整份时间共同限制。错误与超限整份失败，不写入截断结果。
- OCR 功能显式配置开启；Docker 提供专门 OCR 构建 target，基础查询镜像不强制增加语言包。主机未安装时返回明确缺失错误，不能静默伪装 OCR 成功。
- 扫描方向和版面影响识别；采用 Tesseract 自动版面/方向策略并验证旋转合成样本。置信值是引擎估计，不是实测准确率。依据：[官方 CLI](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html)、[质量与分段说明](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html)。

## 验收

正常原生 PDF 不调用 OCR；扫描中文/英文关键内容可提取；混合 PDF 原生页/扫描页均可定位；旋转输入可识别；重复文本受控；空白页明确标识；页数/像素/时间/输出预算及引擎缺失失败有稳定错误；进程/临时目录清理；真实 Boot jar + 受限 Linux 容器验证并记录引擎/语言包版本。不操作业务数据或部署现有服务。


## 实现与验证结果

- 缺省关闭；worker 使用 OCR 镜像 target，基础 runtime 保持轻量。只处理 PDF 的缺文/少字含图/大图页；纯原生页免 OCR，全白页明确标识；保留原生文字，整行按出现次数抵消重复，不删子串/重复表值。
- 子进程固定 CLI、环境最小化、原文不上传外部；候选页/像素预检查、页和总截止、输出大小限制；低置信、空结果或超限整份失败。关闭 JVM 时先触发 shutdown hook 清理 native，再有界强杀可见后代。
- 新来源字段和 `knowledge-structured-v3` 配置 profile 已落盘；旧准备快照继续直接回读，不重新识别。
- 43 项聚焦、703 项完整回归（0 失败/错误、10 项外部集成跳过）；后续 profile/旧快照兼容 11 项、去重补测 9 项通过。具体顺序和命令见 TEST_RESULT。
- 真实 Boot jar 在只读/非 root/禁网/3 GiB/2 CPU/256 pids 容器通过 7 场景：原生、英文、中文、混合跨页、旋转、同页混合、原生加空白；关键内容、来源策略和临时目录清空均通过。Tesseract 5.5.0，语言包 4.1.0；[固定报告](KDP-06-C-ocr.json)。单份冷启动包含解析约 1.23～4.24 秒，整容器峰值 570646528 字节，只说明该合成运行，不是容量承诺。
- 可复现：先执行 TEST_RESULT 的 Maven package/测试，再运行 `python3 deploy/test-parsing-ocr.py`。首次系统包下载需网络；运行期禁网。之前 Ubuntu HTTP 502/索引连接失败，改官方 HTTPS、有界重试并保留签名校验后构建通过。

## 发布与回退边界

此处没有生产部署。可先部署包含引擎的新 worker，但保持开关关闭；通过实际业务样本验收再配置开启。关闭开关只影响尚未准备的新任务；已绑定快照/索引不自动重写。复杂多栏/手写/跨页表格与图形内容仍不保证识别，追加 OCR 不保证阅读顺序。fork 不提供完整恶意文件/进程容器隔离，Xmx 不包含 native RSS；保留外层容器额度和人工处置通道。
