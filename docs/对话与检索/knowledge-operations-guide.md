# 知识运营闭环

控制台 RAG 工作台的「知识运营闭环」支持主动反馈 → 人工修订 → 内容契约检查 → 审核 → 实际入库 → 检索复查 → 再反馈。正式反馈、候选、证据、审核和发布意图存于 MySQL；不在浏览器或进程内保存权威运营状态。

## 启用条件

- 先按 [数据库迁移说明](../平台工程/database-migrations.md) 执行 `knowledge-ingestion` 迁移到 V4。业务账号仅需 DML；应用启动检查表存在，不执行建表。
- `RAG_INGESTION_STORE=jdbc`，复用已有 `RAG_INGESTION_DB_*` 配置。角色为 `combined` 或 `ingest-api`。内存开发模式访问运营接口返回503，不假装保存成功。
- 发布复用现有 S3原文、持久化入库任务和 worker，生产继续要求持久化 registry/向量索引及既有权限配置。只有入库所有必需 sink 达到 READY，运营记录才显示已发布。
- 网关 `/rag/operations/**` 随入库路由进入 `KNOWLEDGE_INGEST_URI`。拆分部署设置 `KNOWLEDGE_OPERATIONS_QUERY_URL` 为实际 query 服务地址，当前 Compose/Helm已配置服务名。它只用于检索复查，不从用户输入取URL。
- combined默认调用本地检索；拆分模式转发本次请求已验证的内部令牌，不保存令牌、不向验签节点分发签名私钥。

## 操作

1. 普通登录用户可在 RAG 工作台输入检索问题、反馈类型、说明及可选文档ID。点击「使用当前检索问题」可显式带入查询，不自动采集整段对话。每个意图生成幂等键，网络失败可重试。
2. 具备 `ingest` 的运营人员打开反馈收件箱或候选列表，基于反馈新建草稿，填写标题、正文、类目和1–20个检查用例。来源反馈必须属于当前租户；新候选获得服务端文档ID。
3. 「检查内容契约」由服务端检查正文是否含用例要求的片段，并保存完整草稿摘要。检查失败不能审核。该检查不是事实准确性、LLM回答质量或线上召回率评测，审核人仍需检查业务事实。
4. 「确认审核通过」记录认证审核者；「发布到知识库」创建真实入库任务并返回202，界面显示发布中。不能将提交成功当成已发布。稍后「同步入库状态」，READY才显示已发布。
5. 发布失败或响应丢失后，由原发布者刷新详情并「恢复发布」，复用固定候选幂等键/原job。其他运营人员可以查看和同步，但不能冒充原发布者重试。
6. 已发布候选可以「复查检索效果」，用当前身份和原问题执行真实检索，验证文档、版本和所需片段。结果保存为独立检索证据；旧版本已被替代时拒绝把新检索结果算到旧版本。
7. 「查看反馈与审计」展示同文档各版本累计的主动反馈数量及最近50条操作记录，不表示全体用户满意度或发布前后因果对照。
8. 需要恢复旧内容时，在旧的已发布候选上点击「用此版本创建回滚草稿」，重新检查、审核并发布新文档版本；当前线上内容不会因创建草稿立即改变。

修改草稿会使旧检查、审核失效。发布中/失败/已发布内容不能原地改写。操作携带修订号，409时界面保留输入；刷新详情后先核对再主动保存，不能盲目覆盖其他人的修改。切换凭证/用户/服务地址会清空运营页面并丢弃旧请求结果。列表每页20条，后端最多100条，审计读取有界。

## 故障与边界

- 503：核对V4迁移、JDBC配置、依赖可用性及检索地址；未知发布结果先刷新/同步，再恢复同一候选。不能换幂等键绕过冲突。
- 403：检查ingest权限、发布者身份、原文档编辑权限和内部身份转发。
- 409：检查修订、状态、发布槽和文档版本。外部入库若抢先更新同一文档，需人工核对入库权威状态；不释放仍可能被执行的版本占位。
- 发布过程不跨对象存储、MySQL和索引建分布式事务。固定幂等键和持久化发布意图用于恢复；原文/索引副作用沿用现有worker幂等协议。
- 反馈内容和草稿正文只有同租户运营权限可管理；反馈关联docId本身不授予文档权限。审计不复制正文。普通用户只能查看本人反馈。
- 当前无自动反馈聚类、自动事实判定、自动发布或定期自动探针。保留/归档期限需要业务另定，未擅自删除审计或承诺备份擦除；持续增长需容量监控。

## 回退与验证

业务内容回退：旧内容生成新候选、重新审核、发布更高版本。代码回退：暂停运营入口/写入，处理或保留已提交入库任务，再回退应用；保留V4表，不删除审计与发布槽。代码回退不会撤销已提交的索引/原文副作用。

隔离数据库验证：`python3 deploy/test-knowledge-operations-mysql.py`，默认复用 dev_infra MySQL8.4，临时库及随机账户在finally中清理。包含持久化重建、租户/用户隔离、幂等、版本、并发审核、发布占位原子性、失败恢复、响应丢失恢复、API契约，检查所有新表字段注释和DML账户禁止DDL。

完整应用链路测试 `KnowledgeOperationsPipelineTest` 使用真实 JDBC任务、应用服务、worker、解析、HashEmbedding与检索，外部原文/向量/registry为离线内存适配器。它不替代生产S3/Qdrant/Redis或真实模型验收。当前结果见 [本轮测试报告](../delivery/memory-knowledge-operations/TEST_RESULT.md)。

## 外部知识源自动同步

产品说明或客服FAQ可通过[HTTP知识源ETL](http-knowledge-sync-guide.md)增量入库，复用现有任务与worker，支持来源更新、显式删除传播和断点恢复。功能默认关闭。
