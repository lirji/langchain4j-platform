# 知识库文档解析生产优化

## 目标与当前链路

2026-10-19，基于 `348c13e` 复核解析、分块、异步入库及恢复。用户授权先记录问题，再按优先级推进修复；主要资料为 **PDF、Word、Markdown、Excel、CSV 和技术文档**。本文维护问题与方案；实施状态、证据及恢复入口统一在 [PROGRESS_STATE](../delivery/knowledge-parsing-hardening/PROGRESS_STATE.md)。

当前链路：上传 → 原文存储 → 持久化任务 → 文本提取 → 分块 → 可选上下文增强 → embedding → VECTOR/ES/GRAPH/AUTHORIZATION → REGISTRY 版本提交。

- [DocumentTextExtractor](../../knowledge-service/src/main/java/com/lrj/platform/knowledge/lifecycle/DocumentTextExtractor.java)：Tika 抽取纯文本。
- [DocumentSplitterFactory](../../knowledge-service/src/main/java/com/lrj/platform/knowledge/DocumentSplitterFactory.java)：recursive、markdown-header、parent-child、semantic；代码缺省 300 字符/50 重叠，实际环境可覆盖。
- [DefaultIngestionDocumentPreparer](../../knowledge-service/src/main/java/com/lrj/platform/knowledge/ingest/job/DefaultIngestionDocumentPreparer.java)：准备完整文档。
- [IngestionJobWorker](../../knowledge-service/src/main/java/com/lrj/platform/knowledge/ingest/job/IngestionJobWorker.java)：租约、心跳及逐 sink 状态。
- [KnowledgeRuntimeBoundaryConfig](../../knowledge-service/src/main/java/com/lrj/platform/knowledge/KnowledgeRuntimeBoundaryConfig.java)：已有 query/ingest-api/ingest-worker 边界，生产模式要求持久化并禁旧写入口。

## 问题清单与考虑

P0 是相关策略投产前的数据正确性问题，P1 是关键稳定性/质量，P2 按语料收益和规模实施。“源码风险”不代表线上已发生；各项实际状态见进度文档。

| ID | 优先级 / 证据 | 问题与原因 | 建议与验收 |
| --- | --- | --- | --- |
| KP-01 | P0 / 离线复现 | 长 Markdown 12 块仅 6 个 ES ID，父子切分 14 块仅 3 个；内层从零编号，ES 按 tenant/doc/version/index upsert | 最终编号全局唯一，父块编号独立；验证多章节/多父块/语义回退及 ES ID，保留租户/版本 metadata |
| KP-02 | P1 / 离线复现 | 代码围栏的 `##` 被当标题；混合 H1/H2 时 `B > Two` 误成 `A > Two` | 使用语法节点和原文位置；覆盖围栏、缩进代码、Setext、HTML 注释及混合层级，保留正文 |
| KP-03 | P1 / 离线复现 | 英文句号不触发语义切句，三句形成一句 | 补边界并保护小数、网址、版本号、缩写和姓名首字母；保持中文行为 |
| KP-04 | P1 / 源码风险 | 短文的语义分位阈值可能落在最大距离，主题变化也不切 | 用短文/多主题基准选择阈值，不未经评测改全局百分位 |
| KP-05 | P1 / 源码风险 | String 结果缺页码、标题层级、表头及原文位置 | 引入结构化内容块；保留页/单元格、标题路径和告警，支持准确引用 |
| KP-06 | P1 / 源码风险 | 非空正文不保证完整，扫描 PDF 仅抽页眉也可能通过 | 页级覆盖、异常、截断及 OCR 结果；部分解析显式说明 |
| KP-07 | P1 / 源码风险 | 正文输出无应用级上限；上传大小不覆盖解压后/嵌套内容 | 分层限制输入/输出/页数/临时盘/块数；超限明确失败，不静默索引截断正文 |
| KP-08 | P1 / 源码风险 | processing-timeout 是持续续期的租约，无法终止卡死解析 | 分离阶段 deadline 与租约；可终止进程、内存/磁盘/网络隔离，验证停止及恢复 |
| KP-09 | P1 / 源码风险 | 重试重新准备却跳过成功 sink，配置变化/语义降级恢复/LLM 输出变化可导致索引不一致 | 固定处理版本和不可变派生清单，所有 sink 读取同一结果；升级用新处理版本 |
| KP-10 | P1 / 源码风险 | 异常统一成 IllegalArgumentException，临时 I/O 也可能按永久失败处理 | 稳定错误分类、安全提示、保留原因链，区分可重试故障与输入问题 |
| KP-11 | P1 / 源码风险 | 旧同步上传未显式关流，底层异常直接进响应头 | 明确流所有权并关闭；返回安全错误，保留 HTTP 契约 |
| KP-12 | P1 / 源码风险 | getBytes 后构造/访问 content 均 clone，验参/哈希/存储多次全量复制 | 先消除内部重复拷贝并保留外部防御性拷贝；再流式接收/哈希，保持幂等指纹 |
| KP-13 | P1 / 源码风险 | Worker 轮询串行处理，长任务阻塞小文件 | 有界并发、租户公平及 OCR 分级；计算多副本 CPU/内存/模型总预算 |
| KP-14 | P1 / 源码风险 | 全文/块/向量驻留，缺统一 token/字节批次预算 | 条数、token、字节共同分批，持久化续做；验证 429 和部分失败 |
| KP-15 | P2 / 源码风险 | 语义切分额外向量化句子窗口；LLM 增强逐块调用 | 结构文档优先结构切分；按检索增益启用昂贵策略，度量每页时间与成本 |
| KP-16 | P1 / 源码风险 | 增强只取前 8000 字符；追加前缀后缺模型真实 token 复核 | 章节/邻近上下文，原文与生成前缀分离；预算包含标题和任务前缀 |
| KP-17 | P2 / 源码风险 | 每个 child 重复存储 parent_text | 测存储放大率，必要时独立父块存储；权衡读取和生命周期成本 |
| KP-18 | P1 / 源码风险 | 解析测试原来仅文本/Markdown/空输入；未测真实 ES ID 冲突 | 小型真实 PDF/DOCX/XLSX/CSV、中文、损坏/加密样本；断言内容而非仅无异常 |
| KP-19 | P1 / 待实测 | 降级仍按请求策略统计；字符大小不能表示质量 | 记录实际策略、阶段耗时、失败类别及覆盖，避免高基数标签 |
| KP-20 | P2 / 待实测 | 缺按格式/页数/语言的吞吐、检索与恢复基线 | 固定样本和问题集；P95/P99、峰值内存、Recall@K、引用准确率、每页成本，不虚构 SLA |

## 主要格式策略

| 格式 | 处理重点与取舍 |
| --- | --- |
| 原生 PDF | 阅读顺序、多栏、页眉页脚、页码与表格；坐标排序不保证所有版面正确，保留原始定位 |
| 扫描/混合 PDF | 按页判断文本质量，选择性 OCR、中文语言包与方向修正；避免整页和全部内嵌图片重复 OCR |
| Word | 标题样式、列表编号、表格、脚注；明确修订/批注规则，避免矛盾版本共同入库 |
| Markdown/技术文档 | 真实语法结构、代码围栏、标题/表格/链接；保留原文，超长代码和表格单独设计切分 |
| Excel/CSV | 表头、工作表、单位、行列、日期、前导零及公式缓存值；不盲目执行公式/外部链接，按行组携带表头 |
| HTML/TXT | 正文 DOM/编码、标题/表格与必要缩进；过滤模板并保留原文映射，乱码明确告警 |
| PPT（后续） | 页级标题、正文、备注/图表；按实际资料占比后续纳入 |

## 实施顺序与兼容边界

1. **KDP-01**：最终分块编号及 ES 唯一性，先补失败用例再修复。
2. **KDP-02**：Markdown 语法边界及英文切句；保留现有配置键和默认块大小。
3. **KDP-03**：解析错误/流生命周期、正文输出预算、上传重复拷贝、真实格式回归。
4. **KDP-04**：持久化不可变派生结果、处理版本与恢复一致性，覆盖存储权限/生命周期/历史在途任务/多 worker，不能用内存缓存代替恢复。
5. **KDP-05**：可终止解析进程、阶段硬截止、有界并发与批次预算；混合负载和停机验证。
6. **KDP-06**：结构化解析、选择性 OCR、格式专项切分与检索评测。

前三项为本轮优先可独立验证的修复；后续项持续记录为待实施，不把基础修复称为全套生产优化完成。新切分规则影响后续入库；历史被覆盖的块需要按新文档版本重新入库，代码发布不会自动恢复。不得自动生产部署、重建索引或删除旧数据。

## 验证与发布

- 分块：唯一 ID、正确标题路径、正文/代码覆盖、租户与版本 metadata 不丢。
- 解析：真实格式、中文、空白、损坏、超限、临时 I/O、关闭输入流。
- 回归：`mvn -pl knowledge-service -am test`；替身模型/存储不代表真实部署验证。
- 恢复专项：KDP-04/05 验证重启、失租、参数变化、部分成功和跨实例；当前风险分析不等同于已验证。
- 独立分支、完整逻辑单元提交、验证后正常合入并推送 main；不强推、不绕过保护、不部署。

## 外部依据

- [Tika 安全模型](https://tika.apache.org/security-model.html)：不可信输入需隔离、资源预算及最小权限。
- [Tika PDF/OCR 配置](https://cwiki.apache.org/confluence/spaces/TIKA/pages/109454066/PDFParser%2BApache%2BPDFBox)：不同 OCR 路径的成本；配置需匹配实际版本。
- [CommonMark Java](https://github.com/commonmark/commonmark-java)：语法节点及 source spans 支持识别真实标题并保留原文。
