# 知识库文档支持范围

核对日期：2026-10-19；主格式结构化解析、选择性 OCR 与其他已注册格式已完成样本验证，处理版本为 `knowledge-structured-v5`。用户主要资料为 PDF、Word、Markdown、Excel、CSV 和技术文档。本文是格式能力清单；实施进度统一见 [PROGRESS_STATE](../delivery/knowledge-parsing-hardening/PROGRESS_STATE.md)，排期与考虑见[生产优化方案](知识库文档解析生产优化.md#下一阶段优先级)。

## 支持口径

- **样本验证**：已通过仓库中的小型格式样本或分块回归，不能推导为该格式所有变体、版面均正确。
- **解析器已注册**：当前项目依赖中的 Tika 声明支持该格式，上传后可走自动识别和提取；还没有本项目对应真实样本的专项验收。
- **专项待建设**：复杂版面、手写、精细坐标等能力不能仅根据解析器注册或结果非空宣称完成。

文件文本提取走 [DocumentTextExtractor](../../knowledge-service/src/main/java/com/lrj/platform/knowledge/lifecycle/DocumentTextExtractor.java)。入口没有只允许下表后缀的业务白名单，二进制按内容识别；CSV/Markdown 的文本内容可能无法单独判别格式，已知后缀用于消歧；下表列的是已核对的常用范围，不是全部 MIME 类型清单。

## 已核对格式

| 文档类型 | 常见扩展名 | 当前证据 | 已验证内容与限制 |
| --- | --- | --- | --- |
| 原生文本 PDF | `.pdf` | 样本验证 | 2/30 页英文原生 PDF、页码定位；混合样本的无文本页告警；加密和损坏安全分类。未验证复杂多栏、跨页表格或中文字体变体，选择性 OCR 见下一行 |
| 扫描/混合 PDF | `.pdf` | Linux OCR 样本验证 | 显式开启；7 个原生/中英/跨页混合/同页混合/旋转/空白场景，页策略与置信信息；低置信/超限整份失败。未验收手写、复杂多栏和跨页表格 |
| Word OOXML | `.docx` | 样本验证 | 中文/200 段长文、Heading 与自定义大纲级别、段落/表格顺序、行组携表头及定位；列表编号/修订/辅助内容有保守告警，不承诺完整语义还原 |
| 旧版 Word | `.doc` | Linux 样本验证 | 真实 OLE 中英正文、编号、切分覆盖；无页/段落结构保证，保留结构不可用告警；未验收复杂修订、宏和嵌入对象 |
| Markdown | `.md` | 样本验证 | 自动识别 Markdown 结构、源行号、ATX/Setext/层级；代码围栏内标题不切章，短代码整块、长代码保留原始字符分段 |
| Excel OOXML | `.xlsx` | 样本验证 | 双工作表、100 行、表头随行组、空列、中文和前导零；公式读缓存不执行，有缓存未重算、隐藏行和合并单元格告警；不声称展开复杂合并表头 |
| 旧版 Excel | `.xls` | Linux 样本验证 | 真实 HSSF 100 行、格式化前导零和中文；复用 XLSX 表头/行组/工作表路径，100/100 行携表头；复杂合并表头未验收 |
| CSV | `.csv` | 样本验证 | UTF-8/BOM、中文、引号逗号/换行、空列/前导零、100 行带表头与逻辑行号；宽/长行分组分片。非逗号分隔与任意编码尚未专项验收 |
| 纯文本 | `.txt` | 样本验证 | UTF-8、带 BOM 的 UTF-16LE/BE 中英文本、空正文与输出限额；不承诺任意编码自动识别 |
| PowerPoint | `.ppt`、`.pptx` | Linux 样本验证 | 两代真实格式的双页中英正文及顺序、切分覆盖；尚无页级来源结构，备注/图表/复杂布局未验收 |
| HTML | `.html`、`.htm` | Linux 样本验证 | UTF-8 与显式 windows-1252、中文/重音字符/表格文字，脚本文本不进正文；复杂去噪/DOM 定位/动态内容未验收，不执行网页 JavaScript |
| 富文本 | `.rtf` | Linux 样本验证 | 完整字体/段落结构的中英/Unicode 文字与切分覆盖；极简缺段落结束标记的文件可能返回 EMPTY，不宣称所有变体可读 |
| OpenDocument 文本 | `.odt` | Linux 样本验证 | 真实 ZIP/manifest/content.xml 的标题与中英正文、切分覆盖；复杂列表、表格关系和辅助内容未验收 |

“技术文档”是内容类别，会按实际的 Markdown、Word、PDF 等格式处理。文件入口先执行格式结构切分；[DocumentSplitterFactory](../../knowledge-service/src/main/java/com/lrj/platform/knowledge/DocumentSplitterFactory.java) 的 `app.rag.chunking.strategy` 继续用于普通结构块内部，缺省 `recursive`。表格和代码采用专用预算规则；旧 JSON 纯文本入口仍沿用显式策略。

## 当前处理边界

1. 文件入口输出有界结构 JSON，再分块、embedding 与索引；主要格式的页/表/行/段落/章节位置进入最终 metadata、准备快照与检索来源。没有 PDF bbox 或任意复杂版面还原保证。
2. 选择性 OCR 缺省开启；标准镜像内置本地 Tesseract 与中英语言包，对缺文、少字含图或大图页识别，保留原生层和页来源。可显式设 `RAG_PARSING_OCR_ENABLED=false` 关闭。引擎置信值不是实测准确率，不能将少量文字或识别成功等同于整页内容完整。
3. 旧同步上传另有图片多模态检索分支，默认关闭，开启依赖配置和模型端点；它不等于文档 OCR，也不是异步文档提取链路已完成同等能力的证据。
4. 文件解析应用默认独立 JVM，含输入/正文/PDF 页数/临时盘预算和硬执行截止；主格式、7 个 OCR 场景及新增 10 个格式/编码场景通过受限 Linux 验证。fork 不是文件/网络安全沙箱，递归附件保持关闭。正文默认最多 2,000,000 字符，超限整份失败；空白、加密、损坏和原文读取故障有不同错误分类。DOC/PPT/HTML/RTF/ODT 当前仍是受限 Tika 正文，不伪造页码或结构。输入、配置与发布约束见[可靠入库接入](可靠入库接入.md#文档解析预算与错误分类2026-10-19)。
